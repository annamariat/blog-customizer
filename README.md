# Проектная работа: Вёрстка и логика панели кастомизации статьи
## Используемый стек:
- Фреймворк и рендер: React, TypeScript (Строгая типизация, хуки, компоненты с пропсами);

- Сборка и сервер: Vite (Быстрая сборка, HMR, поддержка TypeScript «из коробки»);

- Стилизация: SCSS, CSS-модули, CSS-переменные (Модульность, переиспользуемые стили, динамические темы);

- Компоненты и дизайн: Storybook (Изолированная разработка и демонстрация компонентов);

- Качество кода: ESLint, Stylelint, Prettier (Линтинг JS/TS и стилей, автоматическое форматирование);

- Типизация и утилиты: TypeScript (строгий режим), clsx (Управление классами, безопасные пропсы и состояния);

#### Функциональные требования

- Открытие/закрытие сайдбара. При клике на кнопку-«стрелку» сайдбар с настройками открывается; при повторном клике на стрелку либо при клике вне области сайдбара — закрывается.
- Отложенное применение настроек. Изменения в форме не применяются к статье мгновенно: они сохраняются во временном состоянии формы (draftState).
- Применение настроек. После нажатия кнопки «Применить» текущее состояние формы фиксируется как актуальное состояние статьи (articleState), и стили применяются к контенту.
- Сброс настроек. При нажатии «Сбросить» состояние формы принудительно возвращается к значениям по умолчанию (defaultArticleState), после чего стили обновляются.
- Механизм стилей. Все визуальные настройки (шрифт, размер, цвета, ширина) управляются через CSS‑переменные, которые уже объявлены в стилях проекта и инициализированы дефолтными значениями. Компоненты отображают актуальные значения на основе текущего состояния.

#### Реализация формы и механики панели

Перед началом реализации продумайте архитектуру:

- Композиция компонентов. Панель состоит из кнопки-триггера, контейнера сайдбара и формы внутри него. Форма собирается из готовых компонентов: Select, RadioGroup, Button, Separator.
- Хранение состояния. Состояние разделено на две части: articleState — актуальные настройки статьи (хранится на уровне страницы/родительского компонента).
draftState — временное состояние формы (хранится в ArticleParamsForm через useState). Это позволяет менять значения в форме без немедленного влияния на статью.
- Передача данных. Данные передаются через пропсы и коллбэки: форма получает текущее состояние и функцию его обновления, а также управляет своим локальным состоянием.

- Порядок реализации: Реализуйте механику открытия/закрытия панели (через проп isOpen и обработчик setIsOpen). Для удобства отладки можно временно зафиксировать isOpen={true} в родителе.

- Соберите форму из компонентов согласно макету, привязав каждый контрол к соответствующему полю в draftState.

- Настройте обработчики изменений для каждого поля (выбор шрифта, размера, цветов и ширины).

####  Передача данных, применение и сброс настроек

На этом этапе реализуйте логику синхронизации состояний и действий.

Состояния и их назначение: 
- articleState: ArticleStateType — актуальное состояние статьи, которое отображается в контенте.
- draftState: ArticleStateType — локальное состояние формы, отражающее текущие выборы пользователя до нажатия «Применить».
- defaultArticleState: ArticleStateType — набор значений по умолчанию (Open Sans, 18px, чёрный текст, белый фон, широкая ширина). Используется для сброса.

Логика действий:
- Изменение настроек. При выборе нового значения в контроле обновляется только draftState. Статья не меняется.
- Применение. По кнопке «Применить» вызывается setArticleState(draftState), что фиксирует новые настройки и обновляет стили статьи.
- Сброс. По кнопке «Сбросить» draftState устанавливается в defaultArticleState. Это гарантирует возврат к заводским настройкам независимо от текущего articleState.

Технические детали реализации:
- Все настройки хранятся как объекты опций (OptionType), соответствующие элементам списков (fontFamilyOptions, fontSizeOptions, fontColors, backgroundColors, contentWidthArr).
- Дефолтное состояние defaultArticleState вынесено в константу в файле src/constants/articleProps.ts и экспортируется для использования в форме.
- Стилизация элементов (квадратики цветов, селекты, радио‑кнопки) реализована через классы, соответствующие выбранным опциям, а глобальные стили статьи управляются через CSS‑переменные.

-  Реализована механика открытия/закрытия сайдбара.
-  Форма собрана из компонентов Select, RadioGroup, Button и Separator в соответствии с макетом.
- Разделены состояния: articleState (актуальные настройки) и draftState (временное состояние формы).
- Настроена логика применения изменений по кнопке «Применить».
- Исправлена логика сброса: теперь кнопка «Сбросить» возвращает draftState к defaultArticleState, что гарантирует корректный возврат к дефолтным настройкам (шрифт Open Sans, чёрный текст, белый фон и т.д.).
- Устранена проблема с «залипанием» стилей при сбросе — теперь компоненты перерисовываются с правильными классами и CSS‑переменными.
